# V2.1 Security and Quota Report

PostgreSQL 16.16 ran on loopback with a fresh disposable cluster. The existing SQL checked RLS, anonymous/authenticated privileges, minute, day and budget ceilings. Twelve independent concurrent connections requested a five-reservation limit: five returned true, seven false and `day_requests` was five. A second test held the transaction lock, confirmed a competing reservation waited, rolled back and confirmed the waiter succeeded with one recorded reservation and 0.01 reserved. The process was stopped. The portable harness requires `PORTFOLIO_AUDIT_DISPOSABLE=1` and a separately supplied `pg` module; it must only target a fresh disposable server.

Next and Hosted model paths check cancellation before reservation, reserve atomically before generation, and fail closed if the quota service fails. Once reserved, model error, timeout, malformed output or cancellation does not refund the conservative reservation. A cancellation during an in-flight reservation can consume quota with no model call. Guardian, clarification and no-evidence results avoid model reservation; local model preview is opt-in and does not share production quota. Mock provider regression tests and integration fixtures check these boundaries, but cannot establish actual provider charges or deployed service configuration.

Hosted excerpt mode has process-local request/concurrency bounds, not a distributed compute budget. Each additional replica increases aggregate allowance. The existing Supabase infrastructure could host a distinct atomic request counter, but the existing cost-reservation RPC is unsuitable for free excerpts and would make its credentials mandatory. This stage documents the boundary and requires a deployment-specific distributed edge/compute control rather than silently changing excerpt availability. See `docs/security.md`.

Grounding requires public eligible current-snapshot citation keys, valid project scope and source provenance. Added deterministic checks catch some number/date substitutions, explicit cross-project naming and English negative claims unsupported by a negatively anchored source sentence. These are heuristics: matching values can refer to different units/subjects, positive claims can contradict negated sources, translations and implicit attribution remain difficult, and injected content can influence a real model. No claim of full entailment or complete prompt-injection defense is made.

Input body/size/time caps, caller cancellation, origin/access checks, anonymous capture restrictions, protected source exclusions and citation URL restrictions are covered by existing fixtures. These tests do not replace a production penetration test. `npm audit --omit=dev --json` and `npm audit --json` returned zero advisories against the lockfile at the time of this audit; advisory coverage and reachability are not a guarantee of safety. No live API key was read or used.
