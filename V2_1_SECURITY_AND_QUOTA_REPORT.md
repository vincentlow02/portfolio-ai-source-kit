# V2.1 Security and Quota Report

PostgreSQL 16.16 ran on loopback with a fresh disposable cluster. The existing SQL checked RLS, anonymous/authenticated privileges, minute, day and budget ceilings. Twelve independent concurrent connections requested a five-reservation limit: five returned true, seven false and `day_requests` was five. A second test held the transaction lock, confirmed a competing reservation waited, rolled back and confirmed the waiter succeeded with one recorded reservation and 0.01 reserved. The process was stopped. The portable harness requires `PORTFOLIO_AUDIT_DISPOSABLE=1` and a separately supplied `pg` module; it must only target a fresh disposable server.

Next and Hosted model paths check cancellation before reservation, reserve atomically before generation, and fail closed if the quota service fails. Once reserved, model error, timeout, malformed output or cancellation does not refund the conservative reservation. A cancellation during an in-flight reservation can consume quota with no model call. Guardian, clarification and no-evidence results avoid model reservation; local model preview is opt-in and does not share production quota. Mock provider regression tests and integration fixtures check these boundaries, but cannot establish actual provider charges or deployed service configuration.

Hosted excerpt mode has process-local request/concurrency bounds, not a distributed compute budget. Each additional replica increases aggregate allowance. The existing Supabase infrastructure could host a distinct atomic request counter, but the existing cost-reservation RPC is unsuitable for free excerpts and would make its credentials mandatory. This stage documents the boundary and requires a deployment-specific distributed edge/compute control rather than silently changing excerpt availability. See `docs/security.md`.

Grounding requires public eligible current-snapshot citation keys, valid project scope and source provenance. Added deterministic checks catch some number/date substitutions, explicit cross-project naming, English negative claims unsupported by a negatively anchored source sentence, and a direct positive action that a source explicitly negates. These are heuristics: matching values can refer to different units/subjects, other positive claims can still contradict negated sources, translations and implicit attribution remain difficult, and injected content can influence a real model. The negative-action check can conservatively reject a valid claim when different events share a verb. No claim of full entailment or complete prompt-injection defense is made.

Input body/size/time caps, caller cancellation, origin/access checks, anonymous capture restrictions, protected source exclusions and citation URL restrictions are covered by existing fixtures. These tests do not replace a production penetration test. `npm audit --omit=dev --json` and `npm audit --json` returned zero advisories against the lockfile at the time of this audit; advisory coverage and reachability are not a guarantee of safety. No live API key was read or used.

**Specific-intent follow-up:** an independent multilingual development probe found three unsupported questions that would reserve quota and reach the model. The application now uses a narrow cost, wage and manufacturer evidence gate for retrieval/supplements and for verified selection paths, with no semantic-threshold adjustment. Tests use fixture credentials and assert zero quota reservations for the three unsupported cases. Vocabulary matching can still miss unsupported facts or reject legitimate paraphrases; this is not a general hallucination or cost guarantee.

**Multilingual grounding follow-up:** counted Chinese/Japanese numerals with common classifiers and years are normalized against Arabic and common English number forms; tests cover valid and incorrect counts in both citation directions. The parser intentionally does not cover all numeral constructions, units, currencies or semantic associations. First-person and selected female-pronoun role claims in English, Chinese and Japanese now require personal-role evidence; traditional Chinese personal-role evidence is recognized. These heuristics can miss other pronouns or responsibilities and can reject supported paraphrases. See IA-12 and IA-13.

**Number association follow-up:** the `01f3f6c` check binds recognized people counts to cited people counts when at least one is explicitly present. Tests reject swapping a year and a visitor count in English, Chinese and Japanese while accepting equivalent `visitors`/`participants` wording. This does not establish which event a count belongs to, handle all unit categories or prevent every numeric contradiction; sparse evidence may not expose a recognizable count, and conservative extraction may reject valid wording.

**Count, date and usage scope:** subsequent intent gates recognize a limited vocabulary for explicit counts, dates and starting use. A standalone 1900–2099 year does not satisfy a count request, which can reject a legitimate count in that range. The usage check distinguishes some creation wording from usage wording but cannot reliably bind an event, date, subject or relation: matching unrelated words can admit unsupported claims and valid paraphrases can be rejected. Test sets inspected before these changes are development sets, not independent proof.

**Rejected comparison experiment:** The scoped retry tested in `4dbf939` caused a question asking for research participant names to qualify two passages that give participant counts but no names. The preparation decision would therefore proceed toward quota reservation and generation; no paid model was called. `05b39d7` reverts the retry and adds a model-reply regression asserting zero quota reservations. This counterexample does not prove all unsupported questions are stopped by the remaining semantic retrieval and lexical intent gates.

The counterfactual was checked in an isolated checkout of `4dbf939`: with the complete four-project corpus and actual local embedding assets, the zero-reservation assertion failed because the fake reservation callback was invoked. The same assertion passes after rollback. A reduced two-project corpus and a missing embedding model masked the issue, illustrating why fixture composition and genuine local retrieval matter.

**Plural comparison scope:** Before this change a plural follow-up could search all public projects and proceed to generation with unrelated evidence. Recognised plural follow-ups now retain the prior comparison's project IDs; the shared answer engine requires evidence for every side, and Hosted excerpt mode returns both sides or insufficient evidence. Topic terms, interrogative cues, explicit quantities and testing-purpose wording are checked against an individual body clause. A fake reservation regression confirms that a one-sided unsupported materials question makes zero reservations. These checks are lexical, not relational proof: coincidental words and wrong relationships within a clause may still pass, while valid paraphrases and facts spanning clauses can be rejected. The 12-case holdout and Hosted fixture are small local/mock tests, not a production or live-model audit.

**Clarification continuation:** A missing comparison topic returns a deterministic localized question without model reservation. A short next answer may retain the two project IDs only after the exact application clarification and a prior plural user request. The assistant message is used as a context cue, never as factual evidence; callers can supply conversation history, so this is not an authorization boundary. Each retrieved public passage still needs the conservative topic/body checks. The same-clause/method-vocabulary rules can be fooled by unrelated relations and can reject supported paraphrases; no real-model safety claim follows.

**Per-request comparison work:** `f75c164` deduplicates topic terms and fails closed before keyword/semantic retrieval when a carried comparison has more than 32 distinct topic terms or more than 18 projects. The project limit matches the evidence-pack maximum. Tests exercise the over-limit paths and verify no quota reservation; legitimate unusually long or large comparisons can be refused. These are local per-request bounds and do not provide a distributed Hosted compute budget.

**Japanese synonym fallback:** After an empty qualified search for a carried comparison, the application may retry once with `検証` changed to `テスト`; the original query still controls scoped evidence eligibility and no threshold changes. The retry performs an extra local retrieval and can admit semantically related but unsupported passages. Explicitly negated testing actions are rejected for recognized affirmative “how tested” comparisons in common English/Chinese/Japanese forms, but the rule is not complete negation or entailment analysis. Development tests verify one fake model call for the supported path and zero reservations for four unsupported questions. The new ten-case confirmation has no live provider calls; no production billing or model-quality claim follows.

A direct local matcher probe using the Japanese affirmative question `両方のプロジェクトはどう検証されましたか？` returned true for `研究\n团队测试了原型。` and `研究\nチームが原型をテストしました。`, and false for `研究\n团队没有测试原型。` and `研究\n原型はテストされていない。`. Reproduce by calling `comparisonTopicMatcher(question).matches(source)` for each string. This tests only the deterministic matcher, not the full retrieval or model path, and does not establish comprehensive negation coverage.
