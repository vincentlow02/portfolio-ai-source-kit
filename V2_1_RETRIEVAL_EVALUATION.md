## Specific-intent evidence gate follow-up

An independent Japanese development probe exposed three unsupported manufacturer, salary or purchase questions that proceeded to generation because semantically similar passages lacked the requested fact. After the narrow gate and selection-path fix, all six unsupported development questions abstained; the six supported development questions retained evidence. A separately authored eight-question confirmation yielded four supported retained in both versions; V2 proceeded to generation for three of four unsupported questions, while V2.1 abstained on all four. Per-query results, corpus and limitations are in `docs/v2-1-evaluation`. This is not evidence that arbitrary unsupported queries are safely handled; it covers a small list of factual intents and can cause false negatives. The original 100-question recall, coverage and unsupported-abstention aggregates remain unchanged; the latest holdout irrelevant-evidence ratio is 27.78% versus 28.77% for V2.

## Scoped retry and subsequent evaluations

Commit `0bee033` adds one extra search only after an empty qualifying result for one explicit, unambiguously scoped project, retaining the existing score thresholds and project restriction. Direct Recall@5 measures raw retrieval and therefore does not capture this assembly retry. This can increase latency and admit irrelevant passages: on the previously inspected fresh set coverage rises 50% to 75%, while irrelevant evidence rises 33.33% to 40%; `f4` still misses. Raw current original and fresh results are `original-v2-1-scoped.json` and `v2-1-scoped.json`.

A four-supported/four-unsupported single-section synthetic confirmation (`scoped-retry-holdout.mts`) shows expected evidence 1/4 V2 versus 3/4 V2.1, unsupported abstention 4/4 both; one supported case remains missed. A three-supported/three-unsupported multisection set initially found two unsupported cases passed the generation decision. Its results were inspected before count/date gating; afterwards 2/3 supported and 3/3 unsupported, so this is development evidence, not a blind holdout. A subsequent two-supported/three-unsupported count/date set exposed creation-versus-use confusion; it was promoted to development before the usage gate, yielding 2/2 supported and 3/3 abstention afterwards. Finally a separately authored two-supported/two-unsupported usage confirmation retained 2/2 supported in both versions and abstained 2/2 unsupported in V2.1 versus 0/2 V2. These tiny synthetic, same-author samples do not estimate production performance. Per-query corpus, decisions and timings are committed under `docs/v2-1-evaluation`; no real provider was invoked and no semantic threshold was tuned against a holdout.

For the six previously inspected fresh queries, the saved one-shot V2 / V2.1 runs have median retrieval times 11.62 / 9.39 ms and median mock answer-path times 15.29 / 14.23 ms, respectively; mock calls total 2 / 3 (the extra call corresponds to newly recovered `f2`). These runs are not controlled latency benchmarks and do not include a real network provider; no performance improvement is inferred. All individual values remain in the JSON.

## Comparison experiment rejected after adversarial testing

The temporary `4dbf939` experiment retried missing comparison sides after stripping project labels while retaining scoring thresholds. A newly authored same-reviewer confirmation, frozen before running, showed complete evidence for 3/4 supported examples versus 1/4 V2 and pre-experiment V2.1, with 4/4 unsupported abstentions. Those numbers are for an experiment that was **reverted**. A later diagnostic probe against the same observed corpus exposed `Compare Harbor and Orchard study participant names.`: neither public source includes names, yet the experiment assembles both passages and decides to generate. The pre-experiment and reverted versions abstain. This is a concrete precision and cost regression, not a real-model quality measurement. The final implementation retains the original retrieval rules; `comparison-development.test.mts` verifies zero quota reservations for this case. Full question-level confirmation, adversarial and 30-case wider diagnostic records are in `comparison-*.json`, with scripts in `scripts/portfolio-chat/`.

The original 100-question metrics on the experimental version remained unchanged, demonstrating that the existing benchmark did not reveal this regression. The temporary experiment also raised the previously observed fresh-set irrelevant evidence ratio from 40% to 50% by adding a one-sided irrelevant `f4` passage; after rollback the final system returns to the earlier 40% and `f4` still has no evidence. One-sided abstention tests did not protect against the two-sided false match. These small same-author data are not population estimates. Keep the unresolved topic-specific comparison failure visible rather than restoring this unsafe retry.
