## Final comparison and fresh confirmation set

The first holdout was inspected during diagnosis, and `h2` was promoted into a regression after it exposed repeated project labels in evidence search. Consequently its later result is diagnostic, not a blind holdout estimate. The fix retries only an empty, explicitly scoped search with duplicate labels removed; it does not change the qualification thresholds. The original 100-case final run retains the same aggregate scores as V2 (`original-v2-1-final.json`). The first holdout's final evidence coverage is 100% and irrelevant evidence ratio 55.56%, but that number is not independent after diagnosis.

A separate six-question fresh set was authored and frozen after the fix, then run once against both V2 and V2.1. Neither version was tuned on these outcomes. Each contains four supported questions, one ambiguous question and one unsupported question. V2 and V2.1 both achieved Recall@5 50%, evidence coverage 50%, irrelevant evidence ratio 33.33%, and unsupported abstention 1/1; ambiguity clarification improved from 0/1 to 1/1. `f2` (Japanese rearrangement) and `f4` (cross-project participant comparison) produced no evidence. `f3` also included an unrelated Tide passage. Four supported cases are insufficient to estimate general performance; these misses remain unresolved. Per-query evidence, actual mock call counts and one-shot timing are in `v2-fresh.json` and `v2-1-final.json`.

The fresh ambiguity question `f5` is also present in the newly added pronoun regression test. Thus that one case is a confirmation of the existing test, not an independent ambiguity sample; the other fresh questions were not used to adjust the implementation. Both the original and independent datasets are too small to support release-level retrieval-quality conclusions.

## Additional independent development probe

`scripts/portfolio-chat/comparison-development.test.mts` tests a different fictional two-project corpus. Two checks pass: an explicit research-interviews comparison returns both research passages, and an unrelated submarine comparison returns no evidence. A third check currently **fails**: `Who did Quill and Bridge speak to during discovery?` returns no qualifying evidence, although both research passages describe interviews. Separately searching each project also returned no qualified matches. Adding the word `interviews` retrieved both passages, but adding unrelated `submarines` to that expanded query also retrieved both; a naive synonym expansion can admit irrelevant evidence. No such expansion or threshold relaxation was adopted. This is a development failure, not a passing test and not a holdout result. The diagnostic test file is intentionally outside `test:offline` and its failing assertion is retained for future remediation.

This does not establish general paraphrase or cross-language recall, and it does not resolve the frozen `f2`/`f4` outcomes. No threshold was adjusted.

## Cross-language specific-intent development and confirmation

A separate 12-query Japanese development probe (`cross-language-development.mts`) found semantic-score overlap: six answerable questions retrieved their labelled sources, while three of six unsupported questions about manufacturer, wages or purchase also qualified unrelated but topically similar evidence and reached the generation decision. In this small development sample their top cosine scores were 0.438, 0.426 and 0.430; a supported query scored 0.395. Simply raising the global semantic threshold would discard relevant evidence. `cross-language-dev-before.json` and `cross-language-dev-after.json` retain the queries, all four chunk scores, evidence and answer decisions.

The resulting narrow source-intent check requires price, wage or manufacturer evidence for explicit questions of those types, including common English, Chinese and Japanese forms. It applies to retrieval and evidence supplements; an incompatible verified selection now abstains before reservation in generation and excerpt paths. This is a heuristic gate: it may reject valid paraphrases, prices not expressed in its vocabulary, or mixed-topic answers, while a matching word in an irrelevant passage may still permit generation. It is not a general classifier, entailment check or guarantee against arbitrary unsupported questions. Selection provenance alone does not imply a price or manufacturer fact.

A separate eight-question confirmation set was authored after the implementation and run once on V2 and V2.1. Four supported cases retained expected evidence in both versions. For four unsupported cases, V2 would proceed to generation for three; V2.1 abstained in all four. The actual mock-provider/quota no-call assertions are in `specific-intent.test.mts`; the confirmation JSON reports engine decisions, not live LLM calls. The sample is too small for deployment-wide estimates. No semantic threshold was changed and no model or service was added. Raw results are `intent-holdout-v2.json` and `intent-holdout-v2-1.json`.
