### IA-16 — plural follow-up lost project scope

- **Classification / module:** Confirmed defect, P1; shared `resolveContext`, evidence assembly and Hosted excerpt path.
- **Code evidence / root cause:** Previously `isContextualFollowUp` did not recognise explicit plural project references, so `resolveContext` returned no projects and search could include all public projects. `dcca1b3`, `6523b85`, `b5e02fe`, `f9ec58e` and `036b31a` carry only recognised plural comparison references and apply a conservative body/clause topic check. Current code is at `lib/portfolio-chat/retrieval.ts:83` and `:135`, `lib/portfolio-chat/b2.ts:156`, and `lib/portfolio-chat/source-reply.ts:60`; the latter returns one cited excerpt per project or insufficient evidence for this case.
- **User impact / reproduction:** Run `scripts/portfolio-chat/plural-context-holdout.mts` with `PORTFOLIO_EVAL_ROOT` pointing to the pre-fix `16401f9` checkout and then the current checkout. After “Compare Alder and Birch”, ask “When were both projects tested?” Before the change the pack included the unrelated Elm project and the excerpt showed only Elm; after it, both expected project passages are returned. Synthetic fixture, no provider call.
- **Fix / regression risk:** Preserve the explicit plural scope and compare each project's evidence; keep singular, mixed and selection-of-one references conservative. The clause and word checks are heuristics, may accept unrelated same-clause facts, and may reject valid multi-sentence or cross-language support. Other plural phrasings are not covered.
- **Acceptance / evidence:** `hybrid-retrieval.test.mts` tests three languages, singular ambiguity, one-sided evidence and zero quota; `test-hosted-integration.mts` checks two actual Hosted citations and unsupported abstention. The independently frozen, same-reviewer 12-case synthetic holdout has 4/4 supported two-sided excerpts, 5/5 unsupported abstentions and 3/3 singular clarifications; it is too small to establish general correctness. A larger independently judged corpus and real-provider evaluation remain required.


### IA-17 — Japanese passive verification recall

- **Classification / affected module:** Confirmed defect, P1; `lib/portfolio-chat/retrieval.ts:83`, `lib/portfolio-chat/b2.ts:142`, and the shared evidence assembly.
- **Code evidence / root cause:** In the original `plural-topic-holdout` `p3`, Japanese passive suffix tokens did not match English evidence and the original query produced no qualified semantic results. `640ab1c` normalizes affirmative passive testing endings and retries an empty carried comparison once with `検証` replaced by `テスト`, preserving the other terms, scope and existing thresholds. `525de60` adds a narrow explicit-negative-action guard.
- **User impact / reproduction:** Run `scripts/portfolio-chat/plural-topic-holdout.mts` before and after `640ab1c`. For “それぞれのプロジェクトはどう検証されましたか？” the pre-change result abstains; the promoted development rerun returns the two expected public passages. This is not an independent holdout result.
- **Recommended fix / regression risk:** The narrow retry improves that form but can misinterpret verification as testing, costs one extra local retrieval and cannot prove relationships. Complete multilingual intent/number matching and independently evaluate negation, unsupported attributes and false positives without changing the original benchmark or tuning on frozen cases.
- **Acceptance / evidence:** `hybrid-retrieval.test.mts:196` checks scoped positive evidence, four unsupported/negative cases with zero quota reservations, and exactly one fake model call on the supported path. The new same-reviewer synthetic ten-case confirmation produces 1/3 supported two-sided results and 6/6 unsupported abstentions; p2 method and p3 count remain misses. The separate eight-case confirmation gives 1/3 supported and 5/5 negative/unsupported abstentions, with the pre-change version also abstaining on those five. Acceptance requires the method/count forms to retrieve the correct evidence, a newly authored independently judged multilingual set to retain unsupported abstention and existing benchmark standards, and supported generation to remain one model call. The observed holdout cannot be reused as a blind estimate. No real model or production quality is verified.
